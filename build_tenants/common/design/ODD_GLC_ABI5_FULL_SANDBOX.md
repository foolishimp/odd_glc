## One native lifecycle

Preparation verifies/resolves/installs the two fixed Products once, binds the
workspace, admits the complete native catalog and performs native conformance.
It may create the sandbox resource root through its existing authorized setup;
it does not create the application layout or run a source-handoff setup Program.
The paid subject begins with one ordinary installed run.invoke#start packet.

The installed generic graph declares this complete path:

1. Native source intake derives full-source inventory, job identity and the
   initial pending-requirements envelope from the admitted raw request.
2. Intent and Product are authored and independently assessed from complete
   role-appropriate source and actual admitted predecessors.
3. Requirements derives grounded terms and paired realization/proof bindings,
   instantiating only allowed installed templates/contracts. Its independent
   assessment and native result admission activate exact binding versions.
   Merely receiving source or parsing a candidate is not requirements readiness.
4. A native context read supplies bounded current worksite inventory and actual
   execution-capability facts. Design author/assessor use that context, active
   bindings and full prior assets to choose layout, dependencies and commands.
5. Native target planning authenticates that assessed Design and owner bounds.
   Existing C0 ownership creates only necessary missing file parents and records
   physical effects. The native bridge then observes the actual files and
   constructs the existing C1/C2 preparation. No host mkdir or target mapping
   based on the scenario name is permitted.
6. C1 constructs governing/code/test artifacts; C0 admits their real replacements.
   C2 invokes the existing native helper against the protected snapshots and
   supplies observed execution. It cannot write protected construction targets.
7. Native evidence-input joins those exact same-invocation results. Evidence
   author and independent assessor compare actual artifacts/execution with the
   job's criteria. Terminal and fresh public result/replay expose the Run and
   exact admitted prefix. The host only observes/reads after the start.

The graph reuses native implementation owners. It contains no copied ABI4.6
runtimeBindingSource, local controller, prompt renderer, evaluator implementation,
event writer, expected worker answer or host-authored execution document.
Stages may carry non-closing or unknown scope; a gate must not be forced to
sufficient merely to obtain a successful demonstration.
