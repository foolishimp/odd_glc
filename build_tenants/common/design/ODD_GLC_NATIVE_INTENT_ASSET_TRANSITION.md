## Declaration and owner join

`native-intent-declarations.mjs` provides one opt-in policy and pure work-order declaration. It receives explicit source/policy paths, asset path and source-method basis. It does not read files or discover relevant source, render an ABI prompt, invoke an actor, edit the worksite, admit evidence or traverse a graph. The existing `native-lifecycle-declarations.mjs` re-exports it; the old lifecycle functions and default selection remain unchanged.

The external qualification configuration uses the already frozen generic consumer composition and installed native-work owner:

```text
complete frozen source and policy data; Intent file initially absent
  -> pure consumer evaluation: structurally absent/falsified
  -> declared repair consequence
  -> ABI native-work invocation in admitted worksite and sole asset write territory
  -> ABI actual after-observation and effect-scope admission
  -> pure consumer source-integrity/presentation evaluation
  -> graph completion for the construction/structure claim only
  -> fresh Public result/replay and exact resulting-subject freeze
  -> separately activated fresh read-only semantic Reviewer
  -> Executive conjunction/disposition
```

HoG controls the graph portion. The later Reviewer/Executive seam is the existing governance relation and is explicitly not an automatic lifecycle stage, host scheduler, or additional graph engine. No F_D evaluator invokes an F_P assessor. There is no host loop between native graph nodes and no local compatibility path for an ABI gap.

## Source, construction and structural evidence

The input basis lists every selected source member with canonical locator, role and exact hash. The worksite exposes its complete bytes, the basis and the full declared Intent policy. The author must read all selected source bodies, conserve outcomes/users/constraints/uncertainties, preserve modality and conflicts, quote the actual source and retain pending obligations. It may write only the declared Intent file. It receives no expected Intent answer and no evaluator source.

The external pure F_D evaluator checks the unchanged source/policy basis, correct observed input bytes, a present UTF-8 Markdown Intent asset, required headings and literal selected-source identities. Its `satisfied` means **structural readiness with independent semantic assessment pending**. These checks intentionally do not infer source completeness or quality from headings, hashes, counts or quotations. A structurally plausible but semantically wrong document can pass; the focused check demonstrates this limit rather than masking it.

The raw native report remains location/gap evidence. A successful tool exit, observation or structural graph result cannot prove that an Intent faithfully preserves the source. No output file or candidate summary can assert an owner scope ruling.

## Independent assessment and preservation

After construction, freeze the actual asset bytes/digest together with source members, policy, task input, native observation/provenance, admitted result and fresh Public replay coordinates. The next fresh Reviewer receives these exact coordinates and independently reacquires both complete source and actual asset. It receives the applicable RC4 Derived Reviewer and project Product/Proof/Owner frame; required evidence cannot be replaced by this HOW or the author's return.

The Reviewer has no subject write territory. If the native-work owner is selected for that separate invocation, its task has empty `writeRoots`; otherwise the ordinary bounded read-only Reviewer activation applies. No continuation/session state from the author substitutes for source acquisition. The Reviewer evaluates every policy criterion as satisfied/falsified/indeterminate with source/candidate evidence and returns only to Executive. Any changed source, policy, Intent, native basis or evidence invalidates the affected assessment; unaffected source evidence retains only its prior scope.

Executive may conjoin structural and semantic evidence for this one IntentAsset. An unsatisfied/indeterminate assessment leaves the asset a candidate and routes a newly selected repair to its owner. No automatic retry, semantic advancement, application closure or release disposition is implemented here.

## Readiness, effect and proof limits

Execution requires an explicitly selected exact ABI archive and admitted installed Public basis. Selecting that basis for a bounded work unit does not change the source-workspace dependency default. The generic consumer graph/runtime stays independent of the selected source and evaluator; required independent semantic assessment follows actual asset construction.

Declaration/evaluator checks cover conserved source bytes, absent assets, exact work/review territories and the structural evaluator's semantic limit. Installed execution and independent semantic assessment qualify distinct obligations. Source implementation and actual worksite outcomes remain separate subjects; retained qualification and work disposition are tracked by T-043.


## Bounded native continuation of selected existing work — 2026-09-22

This additional callable consumes an ordinary native continuation input with
job data and the unchanged ABI native-command-reacquisition request. It does
not replace the Intent transition or legacy lifecycle route, and claims no
source-to-Design generation. Requirements/Design source and available producer
provenance remain explicit selected evidence; caller supplied plan identity
alone cannot establish semantic derivation or an admitted lifecycle result.

One canonical route-one-typescript Product/Program/package supports every job.
The job selects source and candidate paths, observed rubric/oracle, plan basis,
criterion evidence roles and semantic evidence expectations. Commands, territory,
toolchain and original work order already reside in the request and its actual
native source. Do not duplicate them into policy or package another scenario.
Exact method/profile dependencies and the generic role policy remain installed
constraints; ordinary job data cannot override them.

Declared traversal is select request -> native reacquisition -> C2 -> one typed
retention of original entry and actual C2 observation -> assessment wrapper.
The retained value is the ABI-owned fixed structural pair; the consumer checks
its exact job/request and C2 task/source relationship in pure preparation before
dependent effects. The pair contract alone makes no consumer-subtype claim.
The wrapper prepares the native read-only task and calls the independently
owned F_P assessor. Its existing workflow judgment receives exact entry plus
actual assessor output, checks task/currentness/provenance/coverage/evidence
roles and selected residuals, and advances only on supported satisfaction.
It neither reconstructs authority from prompt text nor manufactures semantic
judgment. No identity branch, second retention or completion carrier is needed.
Root closure conserves current authority/subject and relies on admitted child
judgment/foldback; failed/blocked or unsatisfied output is preserved.

The source contract and two generic actor roles belong to the canonical native
continuation module and ABI5 package producer. The historical 0.1.0 ABI4.6 root
package and existing lifecycle exports are unchanged. Scenario job packets,
local paths, oracle content, expected output markers and command choices stay
outside package inventory. ABI owns effects, source admission, event truth,
replay and all Public preparation; odd_glc owns only this declared bounded
policy and pure interpretation of actual typed evidence.

Qualification first checks raw/installed E/S/T ownership and real route/cold
readmission, then two different job packets against identical Product, Program,
implementation, schema and role identities. Component assumptions, absent plan
provenance and remaining native execution are explicit. This is not full
lifecycle or release qualification, and does not authorize application edits.

An evaluation-only oracle is selected ordinary job data: either an exact observed
file coordinate or `{ref, digest, text}` whose byte digest is checked. Its exact
label and bytes reach only the assessment work order and quote interpretation.
This preserves a previously external oracle without adding it to installed
semantics or requiring a new file in a preserved worksite. It supplies no method,
run-environment, source-admission, or capability authority.
