# odd_glc Intent

**Status**: Active
**Date**: 2026-06-27
**Derived From**: `.ai-workspace/context/project_bootstrap.md`

## Purpose

`odd_glc` exists to provide an ODD General Life Cycle framework over admitted
GTL/ABG truth.

It gives general lifecycle meaning to requirements, spans, projections,
evidence, folds, residuals, replay, re-entry, release pressure, and
operational feedback without moving that runtime truth out of ABG.

## Outcomes

The project must deliver:

- lifecycle vocabulary for general ODD work;
- typed lifecycle assets and graph-function carriers;
- lifecycle read models over admitted ABG/GTL requirements-algebra truth;
- default `F_P` prompt and evaluator boundaries for lifecycle interpretation;
- explicit `F_H` decision surfaces for human-governed lifecycle choices;
- proof surfaces for lifecycle closure, residual pressure, release readiness,
  and re-entry;
- downstream specialization contracts for products such as `odd_sdlc`;
- a build-tenant realization only after the graph-function and proof shape is
  ratified.

## Constraints

- `specification/` is the authoritative `WHAT`.
- `build_tenants/` is realization `HOW`.
- ABG owns traversal, runtime facts, event replay, continuations, correction,
  folds, residuals, and re-entry truth.
- GTL owns the graph-native declaration and wrapper language.
- `odd_glc` owns lifecycle meaning, lifecycle graph-function semantics, policy
  overlays, query projections, and domain proof interpretation.
- `odd_glc` must not implement a product-local requirement compiler, writable
  closure ledger, runtime loop, retry controller, or replay authority.
- Domain products own domain-specific policy and evidence interpretation.
- Shared method changes belong in `specification_methodology`, not by
  repetition inside `odd_glc`.
